## Method

The 54 crates under `rustd/crates/` were split into seven groups (the spec's six, with the runner group halved,
because its 73,000 lines would not fit one reader). Per group, a finder agent read every `src/` file and proposed
rows; a separate verifier agent saw only the rows and the source, never the finder's reasoning, and tried to refute
each — a replacement that differs on some input, error, edge or order; an edge that breaks a dependency rule; a prior
decision that covers it; a lookalike rather than a duplicate. Two workspace-wide passes ran beside them: the
cross-group pass (X) took every private function name defined in three or more crates and every seeded family's grep
across all 54 crates, and the LOG pass typed every log site that renders a failure. Only confirmed rows were
implemented; refuted rows stay below with the refutation as their status.

Implementation applied two rules beyond each row. The milestone changes observable behaviour in exactly the ways the
spec names (a log's `reason` for a coded failure is `Coded::told()`; a client that must reach its endpoint directly
ignores an environment proxy and refuses boot if it cannot build) plus defect fixes that tighten a security boundary;
a confirmed row whose replacement would change anything else — a response byte, an accepted input, a stored string,
the order refusals are asked in — landed in its behaviour-preserving form, or was refuted with the input that changes.
