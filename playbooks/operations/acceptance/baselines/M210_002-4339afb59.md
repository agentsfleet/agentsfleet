## Two timeouts under machine load

The first `orly gate pr` run on `275c1e509` saw two tests time out. Neither
test's file changes on this branch (`git diff --stat origin/main...HEAD` over
both prints nothing), and the machine's load average was 18.87 at the time
(`uptime`), driven by macOS's own `suggestd`, `syspolicyd` and `mds_stores`.

| Test | Under the gate | Alone |
|---|---|---|
| `afd_outbound` `lanes::answers_to_one_destination_leave_in_the_order_they_were_queued` | timed out at its 30 s acknowledgement wait (`lanes.rs:117`) | passed in 0.49 s |
| `agentsfleetd` `integration_rust_runner::test_rust_runner_lease_roundtrip` | no lease row by its 60 s settle deadline (`integration_rust_runner.rs:129`) | passed 3 of 3, in 6.79 s, 51.89 s and 5.75 s |

`make/test-integration-rustd.mk` records why the second is exposed on the shared
lane: a runner leases any fleet whose tags it carries, so beside every other
scenario it can be handed fleets those scenarios left behind. The coverage lane
gives it its own datastores for that reason.

The 51.89 s solo run is open. The test drives a `ScriptedEngine`, not the new
agent loop, and this branch does not touch the runner's polling path
(`worker_pool.rs`, `client.rs`, `lease_loop.rs`); the no-work poll pause is
1 s (`afd_core/src/timing.rs:68`) and the supervisor's join timeout 10 s
(`agentsfleetd/src/supervisor.rs:52`), so neither explains a 45 s swing. The
same test at `4339afb59` has not been timed, which is what would say whether
the spread predates this branch.
