## Where the +7 Rust unit tests come from

All seven are the fault split, and they divide by what they can prove:

- `producers/fleet/runner/tests.rs` (three) — the CLASSIFICATION.
  `every_failure_class_is_assigned_the_side_we_decided` walks all eleven
  `FailureClass` members against a hand-written table;
  `the_split_covers_every_class_the_wire_can_carry` pins the count at 11 so a
  twelfth cannot land undocumented; `an_unclassified_failure_is_charged_to_the_platform`
  holds `None` on our side.
- `tests/runner_fault_label.rs` (four) — the LABEL AS EMITTED, which the three
  above cannot reach. Read back through the capturing exporter, where
  `Capture::sum` matches the exact label set. The fourth,
  `should_leave_a_success_without_a_fault_label`, is the one that matters: a
  `fault` written onto `processed` would move every successful run out of
  `{fault!="workload"}` and the objective would read healthy while measuring
  nothing.

Four mutants, four killed: a success given a fault label, `OomKill` moved to the
platform side, `None` defaulted to the workload, and the harness `declare -F`
guard deleted. Each failed exactly the test that claims it.

Integration is flat at 493 because this branch's new tests are all unit: the
dashboard and gate work is asset JSON and shell, graded by the observability
playbook suite (23 tests) and `01_assets_check.sh`, neither of which is a
cargo lane.

## Dragonfly v2.0.0

The final integration lane ran against `dragonflydb/dragonfly:v2.0.0`, which
this branch also takes. v2.0.0 changed RESP3 null encoding for blocking list,
stream and sorted-set commands, the `XREAD BLOCK` map shape, and cluster
migration finalization — all on this daemon's transport. The lane covers them:
`test_sharded_subscription_survives_slot_movement`,
`test_cluster_primitives_survive_movement`,
`test_cluster_preserves_application_outcomes`, and the stream, lease and claim
suites that block.

One bound worth stating: `make/test-infra.mk` runs `docker compose up -d --wait`
and never `down -v`, so the named volume persisted from v1.40.2 runs earlier the
same day. v2.0.0 therefore read a v1.40.2 `/data` — but that `/data` held the
cluster layout, the slot file and minted certificates and **no `.rdb` or `.dfs`
snapshot**. Snapshot loading across the major version is untested here.
